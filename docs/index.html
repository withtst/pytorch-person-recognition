阶段 0.1 · 数据体检与清洗

本节核心：写模型之前，先看清数据。 数据工程是深度学习的第一步，垃圾进则垃圾出。

做了什么

  • 用脚本遍历 11 个人物文件夹，统计每人图片数、格式分布、尺寸分布
  • PIL 深校验（img.verify()）找出损坏图片
  • 发现异常文件 5 个：3 × HEIC（苹果格式）、1 × txt、1 × 损坏 PNG
  • 隔离式清洗：异常文件移动到 data_quarantine/，未删除任何数据
  • 得到干净数据集：11 类 / 4384 张（jpg 115 + png 4269）

学到的关键点

  • 效率 大数据处理第一戒律：别重复扫描目录。一次遍历生成"文件档案"，所有统计复用
  • 可复现 os.listdir 结果顺序不保证，一律 sorted() —— 今天的报告明天还能对上
  • 陷阱 Image.open() 是懒加载，只读文件头 ≠ 图片完整；img.verify() 才读像素
  • 陷阱 跨平台脚本 stdout 别用 emoji —— ✅ 在 Windows GBK 终端直接 UnicodeEncodeError（真实踩坑）
  • 偏差 类别极度不均衡：tifa 只有 79 张 vs 洛瑶 763 张（近 10 倍），模型会偏向多数类

思考题 & 答案

❓ 为什么图片尺寸不一样会对训练造成困难？

网络全连接层要求输入维度固定，图片必须先 resize 成统一尺寸；尺寸差异大会让特征被拉伸变形，所以还需要 CenterCrop/RandomCrop 等策略（第 1.2 节展开）。

阶段 0.2 · 最小 PyTorch 程序

本节核心：认识 autograd 之前，先认识 tensor 的世界观。 所有后续内容都在这一页的地基上。

做了什么

  • 创建 tensor，观察 dtype / shape / device 三件套
  • GPU 觉醒：torch.cuda.is_available()=True，硬件 NVIDIA GeForce RTX 5070，x.to("cuda") 完成迁移
  • autograd 初体验：c=a*b 求导，a.grad=4.0, b.grad=3.0（∂c/∂a=b=4 ✓）
  • 标量化求导：y=(x×2).sum() → x.grad=[2,2,2]（∂y/∂xi=2 ✓）

学到的关键点

  • 坑 .to("cuda") 返回新张量，原地使用必须 x = x.to("cuda")，否则 device 纹丝不动（真实踩坑）
  • 坑 整数张量无法 requires_grad=True；非标量 backward() 直接报 element 0 of tensors does not require grad
  • 原理 autograd = 计算图 + 链式法则。每个算子注册反向函数（sum 的反向 = 全 1 加权），梯度沿图反向传播
  • 原理 backward(gradient=v) 通用含义是 Jᵀ·v（雅可比转置 × 向量）；标量 loss 默认 v=1 —— 这就是为什么 loss 一定要是标量
  • 硬硬件 RTX 5070 就位：后续训练全部跑 GPU

阶段 1.1 · 手写 Dataset 类

本节核心：Dataset 只是"按编号取数据"的抽象接口——两个方法 __len__ + __getitem__，学会它你就看懂了所有数据管线。

做了什么

  • __init__ 一次扫描建文件清单 [(路径, label), ...]（复用 0.1 的"别重复扫描"原则）
  • class_to_idx 编码：sorted() 后 enumerate 编号，可复现的类别映射；附倒查表 idx_to_class
  • __getitem__ 四步管线：convert("RGB")（吸 Alpha）→ resize(256, LANCZOS) → permute(C,H,W) → /255 float32
  • 字节预算思考：256×256×3×4B ≈ 786 KB/张 → batch 64 ≈ 50 MB；如果 2048 会直接爆显存

学到的关键点

  • 坑 PNG 约 97% 带着 α 通道，convert("RGB") 返回新图，必须接住返回值
  • 坑 permute(2,0,1) 把 (H,W,C) 变成网络约定的 (C,H,W)——维度顺序是 PyTorch/NumPy 的历史差异，写错会"静默训练失败"
  • 原理 len() 决定 DataLoader 一个 epoch 的步数；__getitem__ 决定网络看到什么
  • 原理 label 用整数 0~10（Long），对应 CrossEntropyLoss 的类索引约定——不要 one-hot 不要 float
  • 设计 transform 参数预留注入点：内部是"保底管线"，外部可传 Compose（第 1.2 节）

阶段 1.2 · transforms 管线

本节核心：官方 Compose 管线 = 我们手写四步 + Normalize，并且用【数值实验】证明了这一点。

做了什么

  • Compose([Resize, ToTensor, Normalize]) 官方管线 vs 手写管线同图对擂
  • 等价性实验：手写四步 vs ToTensor → 最大偏差 0.00e+00（逐像素一致）
  • 数学验证：(x-0.5)/0.5 vs Normalize([0.5]*3,[0.5]*3) → 偏差 0.00e+00
  • 抽样 200 张统计：本数据集通道真实均值 ≈ [0.598, 0.552, 0.514]——比 0.5 高，说明图片整体偏亮

学到的关键点（含一场硬核 Debug）

  • 坑 ToTensor 不含 resize！偷懒不写 Resize 的下场：2727×1536 原图直进网络（实测报错）
  • 地雷 T.Normalize(0.5, 0.5, 0.5) 含义是 mean=0.5, std=0.5, inplace=0.5！第三个位置参数是 inplace，0.5 为真值导致原地修改、返回原对象、输出时真时假 —— 排查近 1 小时
  • 正确姿势 Normalize([0.5,0.5,0.5], [0.5,0.5,0.5])：永远传 列表，且用【数值】验证而非 is
  • 原理 Normalize 把 [0,1] 映射到 [-1,1]：零均值输入让梯度脱离"单侧符号"束缚，各通道同一尺度（详见 0.2 节梯度解析）
  • 伏笔 数据集真实 mean≈0.55 而偷懒用 0.25/0.75 归一化后均值残余 ≈ +0.03~+0.20 → 第 3.2 节将计算真实通道统计量取代 0.5 猜测

阶段 1.3 · DataLoader

本节核心：DataLoader = dataset 的"出餐窗口"——batch_size / shuffle / num_workers / drop_last 四个参数全部亲手做过实验。

做了什么

  • next(iter(loader)) → x.shape=(32,3,256,256)，B=32 由默认 collate_fn 的 torch.stack 打包出来（x[i] 与 y[i] 永远是同一样本）
  • shuffle 对照：不 shuffle 时整批是"一个人的连续切片"；shuffle 后一批混进 11 个人
  • drop_last：4384 = 64×68 + 32 → len(loader) 69 vs 68；尾巴 32 张单独建立子集验证
  • 计时：num_workers=2 每 epoch 提速 1.65×（37.95s → 22.96s，真实测量）

学到的关键点

  • 原理 DataLoader 是迭代器：构造不花时间，迭代才真正解码——所以"一个 epoch"= 迭代完全部 batch
  • 原理 shuffle 打乱的是 索引序列（RandomSampler），不是数据；__getitem__ 必须保持"同索引同样本"的纯函数
  • 坑 Subset(ds, range(512)) 直接取前 512 张会全部是同一个人——分层取样（每类 47 张）才是正确子集姿势
  • 坑 Windows + num_workers>0 必须 if __name__ == "__main__" 守卫，否则 spawn 递归爆炸（bootstrapping）
  • 实证 机制实验用 517 张分层子集（不然 4384 张 LANCZOS 解码一个 epoch 要 3-4 分钟——数据是第一瓶颈的活证据）

阶段 1.4 · 数据集划分 train/val

本节核心：val 是"没见过题的监考老师"——划分策略决定你能不能"看清模型收没收敛"，比调参重要得多。

做了什么

  • random_split 80/20：train=3508 / val=876（索引级切割，零数据搬运）
  • 种子纪律：不设种子跑 5 次，tifa 的 val 张数 [14, 16, 10, 18, 22]——剧烈漂移；manual_seed(42) 后 5 次全为 16
  • 事故实拍：随机划分下各人 val 占比漂到 14.2%~23.7%；分层划分后全部收敛到 19.7%~20.3%
  • 交付 get_datasets()：分层 + 固定种子 + 独立 numpy 随机源，为 2.x 训练循环开好接口

学到的关键点

  • 原理 划分是索引集合的切分（Subset.indices），数据集共享同一份文件——所以"改数据"和"做增强"必须发生在读取管线而不是数据集本身
  • 工程规范 不固定种子的 5 次划分 = 5 个不同数据集，实验对比全部作废；固定种子后 5 次全等（16/16/16/16/16）
  • 设计 分层抽样：按类拆桶、桶内各切 20%（含四舍五入），tifa 79 张稳定分到 val 16 张（20.3%）
  • 取舍 为什么不用 K 折：K 倍训练成本 + 我们的 val 只当"防过拟合哨兵"和"best model 选评委"，固定一刀足够；深层学习是"快速迭代派"不是"统计严谨派"
